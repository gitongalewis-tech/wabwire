WABWIRE EMAIL SETUP WITH RESEND
================================

What this project already does
------------------------------
The backend sends campaign emails through Resend's HTTPS API. It reads two
server-only settings from backend/.env:

  EMAIL_API_KEY=
  EMAIL_FROM=

Do not put either value in frontend/.env, a VITE_ variable, source code, or a
message/chat. Never commit backend/.env. It is ignored by Git.

Setup steps
-----------
1. Buy or use a domain you control (for example, your Wabwire website domain).
   Resend requires ownership of a verified sending domain; it cannot send
   production mail from an address you do not control.

2. Sign in at https://resend.com and open Domains > Add Domain. Use a sending
   subdomain such as mail.yourdomain.com or updates.yourdomain.com. This keeps
   email reputation separate from the main website domain. Select a region
   near most recipients.

3. Resend shows the exact DNS records for the domain. Open the DNS control
   panel at the domain registrar, add the records exactly as displayed, and
   return to Resend to verify. Add the provided DKIM and SPF-related records.
   Do not guess these values or overwrite existing DNS records; copy Resend's
   records exactly. If a DNS provider offers proxying for CNAME records, turn
   proxying off for Resend's verification/sending record. DNS may take time to
   propagate. Resend recommends adding DMARC after domain verification.

4. In Resend, open API Keys > Create API Key. Name it Wabwire backend. Choose
   Sending access and restrict it to the sending domain if the dashboard offers
   that option. Resend displays the secret only once, so copy it directly into
   the backend environment and keep it private.

5. Edit wabwire/backend/.env (copy backend/.env.example if needed), filling:

  EMAIL_API_KEY=re_your_secret_key_here
  EMAIL_FROM=Wabwire <notifications@mail.yourdomain.com>

   The address after the display name must use the verified domain/subdomain.
   Use a real mailbox for replies if replies are expected; this application
   currently sends messages as text-only emails and does not configure reply
   routing.

6. Restart the backend so it reads the new environment values. In Admin >
   Communications, create an announcement and use a test recipient that you
   control before sending to active members. Email campaign sending is for
   opted-in/appropriate recipients; honor applicable consent and unsubscribe
   requirements before using bulk announcements.

7. In production hosting, add EMAIL_API_KEY and EMAIL_FROM to the BACKEND
   service's private environment-variable settings. Do not put them in the
   frontend hosting project. Redeploy/restart the backend after setting them.

Troubleshooting
---------------
- The admin screen will report that email delivery is not configured if either
  variable is empty.
- A provider 401/403 usually means the key is wrong, revoked, or lacks sending
  permission. Create a replacement key and revoke a key if it may have leaked.
- A sender/domain error usually means EMAIL_FROM does not match a verified
  domain or the DNS records have not verified yet.
- If requests are accepted but mail is not delivered, inspect Resend's email
  logs, bounces, suppressions, and recipient address. The project reports
  accepted send requests; it does not currently reconcile delivery webhooks.
- Never paste your API key into the repository or browser developer tools.

Current Resend free transactional allowance is listed as 3,000 emails/month,
with a 100-per-day limit. Plan limits and prices can change; check
https://resend.com/pricing before launch.
